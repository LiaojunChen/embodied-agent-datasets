统计口径

token 是怎么数的
  • 文本 token：用 Qwen3.8 tokenizer 对每条样本的可训练字段计数，即对话、工具定义、任务描述和答案。元数据、ID、URL、哈希、质量评分、连续动作 / 状态数组不计；浮点数按 4 位有效数字计。
  • 抽样方式：每个文件抽约 400 条，覆盖文件的多个位置。parquet 读多个 row group，且不读图像列；json / jsonl 在 16 个位置做 HTTP 区间读取。条目内其余文件按字节外推。多子集的大仓库（FineVision、MolmoAct、EO-Data 等）每个子集至少测 1 个文件，再用 HF /size 接口的精确行数放大。
  • 视觉 token：。每个数据集按实测分辨率估算单张成本，如 OXE 帧约 64–106、手机截图 1024、EO-Data 帧 90。
  • 去重：同一批数据的多种渲染只计一份，例如 Aguvis l1/l2/l3、Toucan 的 Kimi-K2 / OSS、Cosmos robovqa_reasoning_1–4、OpenResearcher 的 16 个 seed、CoderForge 的 filtered_reward1。被其他合集完整包含的条目标为“已包含”，不计入配比。
  • gated 数据集（xLAM、MiroVerse、UGround）无法直接读取，按 card / 论文估算，页面标为“估算”。
  • 样本数：parquet 来自文件元数据或 HF /size 接口，是精确值；大 json 文件用字节数除以平均单条字节数估算。
  • 误差：大多数条目在 ±15% 内。长度分布极不均匀的条目误差更大，例如 SWE-rebench CodeWorldModeling：按行数估约 147B、按字节估约 223B，页面取前者。
